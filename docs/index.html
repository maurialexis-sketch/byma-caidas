Bandas de Bollinger (estrategia del BACKTEST y señal «Bollinger» de esta lista)

La entrada y la salida por tramos se definen en la pestaña BACKTEST (Reglas y supuestos). Los pesos de los tramos son relativos (1-1-1 = un tercio cada uno). Los de salida y el stop solo cuentan para el backtest; la lista de candidatos usa la entrada. El período de la media central, las velas y la ventana de los dos listados («en caída» y «cambio de pendiente», más abajo) también se cambian acá: el período de los listados es propio (20 por defecto) y no cambia el de la estrategia de Bollinger.
Fijos, no editables (estructura del cálculo de niveles): ventana de 8 meses (168 ruedas) · 2 o más toques · tolerancia 2% · stop = soporte − 1%.
«Correr ahora» usa estos valores. Si la corrida sale bien, quedan guardados para las siguientes, incluida la automática de las 18:00. Si los cambiás acá y no corrés el informe, no se guardan.
Permiso para lanzar desde acá (una sola vez)

Para que el botón lance la corrida hace falta un permiso de GitHub (un «token»). Se crea una vez y queda solo en este dispositivo.

  1. Abrí la página de GitHub para crear un token (fine-grained).
  2. Repository access → Only select repositories → .
  3. Repository permissions → Actions: Read and write. Ningún otro.
  4. Elegí un vencimiento, generá el token, copialo y pegalo acá.

Ese token solo puede lanzar, consultar y cancelar corridas de este repositorio: no puede cambiar código ni ver tus informes. Se guarda sin cifrar en este navegador y «Cerrar sesión» lo borra. Si perdés el dispositivo, revocalo en GitHub.

Sin permiso también podés lanzarlo a mano: abrir en GitHub → Run workflow (ahí cargás los mismos cuatro valores).
